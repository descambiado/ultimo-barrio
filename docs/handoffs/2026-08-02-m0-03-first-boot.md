## Resultado comprobado

- Existe `Assets/scenes/main.scene` y el proyecto la usa como escena de inicio.
- La jerarquía contiene los roots `World`, `Systems`, `SpawnPoints` y `Debug`.
- `World` contiene suelo provisional, luz direccional y cielo.
- `SpawnPoints` contiene un punto de aparición provisional.
- `Systems` contiene una cámara y una instancia del prefab oficial
  `Player Controller` de s&box.
- Los ensamblados de runtime y editor compilaron con 0 errores y 0 avisos.
- Play Mode inició y se detuvo correctamente en `main.scene`.
- La consulta de consola no devolvió errores del proyecto durante la prueba.
- El jugador apareció visible y la cámara produjo una imagen válida. La
  evidencia está en `docs/media/first-boot.png`.

La captura demuestra que el jugador se instancia y que la cámara renderiza.
No demuestra que el jugador responda a movimiento o a control de cámara.

## Pendiente de verificar

- Movimiento mediante input real.
- Control de cámara mediante input real.
- Ownership y movimiento independiente en una sesión con dos clientes.
- Conexión y desconexión de una segunda instancia.
- Consola separada de host y cliente durante esa prueba.

consola, pero no inyecta teclado o ratón ni abre una segunda instancia de
cliente. Por eso estas comprobaciones no se marcan como completadas.

## Ruta técnica verificada para M0-04

La instalación oficial local confirma el flujo de prueba con dos instancias:

- El menú del viewport usa `EditorUtility.Network.StartHosting` para iniciar
  hosting.
- `Join via new instance` lanza `sbox.exe -joinlocal +instanceid <N>` y puede
  añadir `-sw -720` para una ventana pequeña.
- La documentación oficial también admite `connect local` y `reconnect`.

Fuentes locales consultadas:

```text
C:\Program Files (x86)\Steam\steamapps\common\sbox\addons\tools\Code\Scene\SceneView\ViewportTools.Network.cs
C:\Program Files (x86)\Steam\steamapps\common\sbox\addons\base\code\Components\Networking\NetworkHelper.cs
```

`NetworkHelper` crea el lobby, clona `PlayerPrefab` para cada conexión y llama
a `NetworkSpawn(connection)`. La escena actual no contiene ese componente y
mantiene un Player directo. Añadir ambos a la vez puede duplicar el jugador del
host, por lo que M0-04 debe convertir el Player en prefab de spawn antes de
lanzar otra instancia.

El lanzamiento está documentado, pero la prueba no se ejecutó: el MCP no
expone el menú de hosting, input independiente ni la consola/cámara del segundo
proceso. No existe evidencia todavía de dos jugadores, ownership, movimiento
independiente o desconexión limpia.

## Cómo repetir la prueba local

1. Abrir `ultimo_barrio.sbproj` en s&box.
2. Confirmar que `scenes/main.scene` es la escena activa.
3. Inspeccionar los roots `World`, `Systems`, `SpawnPoints` y `Debug`.
4. Comprobar que runtime y editor indican 0 errores y 0 avisos.
5. Iniciar Play Mode y confirmar que el jugador aparece sobre el suelo y la
   cámara renderiza la escena.
6. Leer la consola y confirmar que no aparecen errores del proyecto.
7. Detener Play Mode y comprobar que la escena no queda con cambios inesperados.

Para cerrar M0-03 todavía hace falta repetir el paso 5 con control real de
teclado y ratón, verificar movimiento y cámara, y dejar ese resultado
documentado. La prueba con dos clientes corresponde al siguiente bloque y no
se ha ejecutado.

## Riesgos y bloqueadores reales

- El estado visible no garantiza que las acciones configuradas respondan al
  input hasta ejecutar la prueba manual en el viewport.
- La sesión multijugador no puede validarse con una sola instancia controlada
  por el MCP actual.
- La publicación remota depende de renovar la autenticación de GitHub CLI.
