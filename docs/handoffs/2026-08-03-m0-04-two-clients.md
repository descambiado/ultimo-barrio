## Cambio estable

`Assets/scenes/main.scene` ya no contiene una instancia directa del Player.
`Systems/Network` tiene el componente oficial `NetworkHelper`, configurado para
crear la sesión y clonar `templates/gameobject/player controller.prefab` para
cada conexión. El `SpawnPoint` de la escena se usa como fallback oficial.

Esto evita el jugador duplicado del host y deja que `NetworkSpawn(connection)`
asigne el owner real de cada clon.

## Evidencia

- El host inició desde `main.scene` y creó un único jugador local.
- `sbox.exe -joinlocal +instanceid 1 -sw -720` conectó una segunda instancia.
- La escena runtime tuvo exactamente dos Players distintos.
- El operador verificó movimiento y cámara independientes en ambas ventanas.
- El cliente mostró el avatar del perfil local.
- Al cerrar el cliente, el host registró salida/desconexión, eliminó su Player y
  mantuvo el Player local.
- La consola del host terminó con 0 entradas `Error` entre 64 almacenadas.
- Los 10 compiladores terminaron con 0 errores y 0 avisos.
- Play Mode se detuvo y la escena quedó guardada.

La guía reproducible y las incidencias están en
`docs/testing/m0-04-two-clients.md`.

## Incidencias no ocultas

1. El segundo jugador apareció inicialmente en el aire. Con un único spawn, la
   hipótesis principal es solapamiento de colliders, pero no está demostrada.
2. El log del cliente contiene errores de recursos del entorno engine/Base
   Library y consultas a escenas compiladas. La sesión fue funcional, pero la
   consola del cliente no se declara limpia.

Estos puntos pasan a M0-05/smoke test y no invalidan la conexión, ownership,
input independiente ni desconexión ya observados.
